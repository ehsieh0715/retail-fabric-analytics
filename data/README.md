# Source Data

This document describes the source-data contract, confirmed profiling
results, preparation outputs, and analytical limitations.

For installation and execution instructions, see
[Reproducing the solution](../README.md#reproducing-the-solution).

## Dataset

The project uses the
[Mexico Toy Sales dataset from Maven Analytics](https://mavenanalytics.io/data-playground/mexico-toy-sales),
published as Public Domain.

The dataset represents a fictional toy-store chain in Mexico and includes
sales transactions, products, stores, a calendar, and the latest supplied
inventory position for each recorded store-product combination.

## Source Files and Local Placement

The source package contains six CSV files:

```text
calendar.csv
data_dictionary.csv
inventory.csv
products.csv
sales.csv
stores.csv
```

Place the extracted files under:

```text
data/raw/maven_toys/
```

The `data/raw/` directory is excluded from Git because the complete source
files can be downloaded from the original publisher.

The original files remain unchanged. Bronze preserves source-aligned
records, while cleaning, validation, and analytical transformation take
place in the downstream Silver and Gold layers.

## Profiled Source Structure

The reproducible source profile is generated by
[`profile_source.py`](../scripts/profile_source.py) and stored in
[`reports/source_profile.json`](../reports/source_profile.json).

| File | Rows | Grain | Natural key |
|---|---:|---|---|
| `sales.csv` | 829,262 | One sales transaction | `Sale_ID` |
| `products.csv` | 35 | One product | `Product_ID` |
| `stores.csv` | 50 | One store | `Store_ID` |
| `inventory.csv` | 1,593 | One supplied store-product position | `Store_ID` + `Product_ID` |
| `calendar.csv` | 638 | One calendar date | `Date` |
| `data_dictionary.csv` | 19 | One table-field definition | `Table` + `Field` |

Sales cover 1 January 2022 through 30 September 2023 and contain
1,090,565 units.

The generated profile confirms:

- no blank values in the six source files
- no duplicate natural keys
- no orphan product or store references in sales or inventory
- no non-positive sales quantities
- no negative stock quantities
- 77 explicitly recorded zero-stock positions
- 157 store-product combinations absent from the inventory file

Source-format inspection also identified:

- currency-formatted text in `Product_Cost` and `Product_Price`
- ISO-formatted dates in sales and stores
- slash-formatted dates in the calendar file

These differences are standardised during Silver transformation rather
than by modifying the original files.

## Inventory Limitations

The inventory file represents the latest supplied stock position and does
not include:

- a business snapshot date
- replenishment events
- stock movements
- purchase orders
- supplier lead times
- recorded lost sales

An ingestion timestamp can record when the file was loaded, but it must
not be interpreted as the business date on which inventory was measured.

An explicitly recorded zero-stock position is different from an absent
store-product combination. Missing combinations remain missing because
the source cannot distinguish an unranged product from an omitted record.

Inventory-risk outputs should therefore be interpreted as current review
indicators rather than historical stock analysis or automated ordering
recommendations.

## Local Preparation Outputs

Local preparation preserves the original source files while producing
repeatable profiling evidence and ingestion inputs.

| Source input | Local handling | Result |
|---|---|---|
| All six source files | Profiled by [`profile_source.py`](../scripts/profile_source.py) | Reproducible results in [`reports/source_profile.json`](../reports/source_profile.json) |
| `sales.csv` | Partitioned by [`create_sales_batches.py`](../scripts/create_sales_batches.py) | 21 monthly files under `data/raw/maven_toys/load_batches/` |
| Five reference files | Retained without source modification | Complete reference extracts ready for upload |

The monthly batches and unchanged reference files form the prepared input
for the OneLake landing zone. Fabric ingestion and deployment are
documented separately in the
[deployment guide](../docs/deployment.md).
